核心仓库名：`sayelf-cq-municipal-cad-qto`

仓库名只代表项目发布身份；Python 核心包仍为 `cad_qto`，AI 插件 ID 仍为 `municipal-cad-qto`，以保持现有导入、MCP 和 Codex/Claude Code/WorkBuddy 配置兼容。命名依据和 GitHub 核验边界见 [仓库命名决策-sayelf-cq-municipal-cad-qto-v0.1.md](docs/仓库命名决策-sayelf-cq-municipal-cad-qto-v0.1.md)。

最短使用路径：

```text
项目管理员建项目和成员 → 各岗位认领任务
→ 填报本周/本月成果并上传证据 → 生产/技术分线审核
→ 造价经理三证互证 → 合格后进入造价系统
```

当前版本是单项目本地演示版，目标是验证以下最小闭环：

```text
岗位任务 → 岗位成果 → 手机照片证据 → 生产/技术审核 → 造价验证
```

项目后续建设统一采用八项底座构建原则，执行清单见 [八项底座构建原则-项目执行清单-v0.1.md](docs/八项底座构建原则-项目执行清单-v0.1.md)。任何新能力都必须先完成现有能力比较、最小范围决策、数据边界检查和聚焦验证。

当前已增加一条本地可验证的图纸算量支线：

```text
ASCII DXF → 标准化 DXF → 图层/实体证据 → 人工确认挡护断面 → 确定性算量 → 待人工审核
```

图纸算量当前支持 `LINE`、`LWPOLYLINE`、`TEXT`、`MTEXT`，并覆盖挡墙墙身、基础、开挖、回填、泄水孔、反滤层、锚杆、抗滑桩、喷射混凝土和钢筋网的显式参数计算。图层识别只产生候选假设；计算结果属于 `Inference`，不会自动成为造价事实。

跨平台 AI 插件包位于 [`plugins/municipal-cad-qto`](plugins/municipal-cad-qto)。它提供标准 MCP STDIO/Streamable HTTP、Codex/Claude Code/WorkBuddy 配置模板、千问/百炼和豆包/扣子私有网关模板，以及 7 个带数据边界的工具（含人工复核落盘）。接入说明见 [`plugins/municipal-cad-qto/README.md`](plugins/municipal-cad-qto/README.md)，决策与验收边界见 [`docs/跨平台AI插件-BDR-v0.1.md`](docs/跨平台AI插件-BDR-v0.1.md)。

## 启动

在项目目录运行：

```text
python server.py
```

默认只监听本机：`http://127.0.0.1:8765`。手机使用时，只有在项目电脑和手机处于同一受控局域网、并由管理员将监听地址改为项目私有网卡地址后，手机才能访问。监听地址和端口可通过 `MUNICIPAL_LOOP_HOST`、`MUNICIPAL_LOOP_PORT` 配置；正式环境应优先由 HTTPS 反向代理承接，不要把演示模式直接暴露到互联网。

本地演示管理员页面：`http://127.0.0.1:8765/admin.html`。正式部署时，该页面必须接入钉钉管理员身份，不能继续使用本地演示权限。

主页面的“图纸算量”可使用合成样例验证：DXF 路径填 `fixtures/cq_retaining_demo.dxf`，断面参数已预置。命令行验证方式（使用项目环境中的 Python）：

```text
python -m unittest discover -s tests -v
python -m cad_qto --input fixtures/cq_retaining_demo.json --output result.json
```

当前 MVP 不内置 DWG/PDF/IFC/LandXML 转换器，也不把 OCR/视觉模型猜测直接作为工程量。原始图纸、标准化图、算量结果和作业审计均留在项目目录；正式版应由私有文件存储和经过审查的本地转换器承接。

正式接入配置模板：`config/dingtalk-qwen.env.example`。真实密钥只放在项目服务器的安全配置中。

当前默认仍为本地演示模式，角色选择仅用于验证流程。正式模式已经提供钉钉授权码、企业成员匹配、实名认证门禁和项目会话适配；角色和项目范围由钉钉稳定用户 ID 在后台匹配，不能由浏览器自行选择。正式上线前仍需用项目租户完成一次真实 OAuth 回调联调。

正式模式还要求钉钉企业成员身份、企业项目成员名单和实名认证核验同时通过；实名状态不能由用户在页面自行填写。部署与联调约束见 `docs/钉钉真实身份适配-v0.1.md`。

## 数据位置

- 结构化项目数据：`data/db.json`
- 现场照片和附件：`data/evidence/`

## 单个项目部部署与使用手册

本节按“一个项目部、一套项目数据、一个统一入口”编写。推荐采用一台项目私有服务器或项目部专用电脑集中保存程序和数据，其他人员通过浏览器、钉钉工作台或 AI 宿主访问；不要让每个人各自维护一份 `db.json`。

### 1. 先确定部署边界

项目管理员先确定以下四项，并写入项目交接单：

- 项目唯一编号：例如 `PROJECT_ID=SZ-2026-001`；
- 造价系统项目编号：必须与最终造价系统一致；
- 项目数据根目录：只允许这一套 `data/`、现场照片、附件和算量作业；
- 项目访问地址：正式使用必须是企业私有域名或私网地址，不使用公共临时链接。

建议目录关系如下：

```text
项目私有根目录/
├─ server.py                 # 主系统
├─ cad_qto/                  # 唯一算量核心
├─ plugins/municipal-cad-qto/ # AI 宿主适配层
├─ data/db.json              # 本项目唯一结构化数据
├─ data/evidence/            # 照片、报告和附件
└─ data/cad_jobs/            # CAD 原图哈希、标准化图和算量作业
```

`data/` 不能放在百度网盘公共分享、个人网盘同步目录或 GitHub。若使用网盘，只能使用企业私有空间，并确认访问控制、回收、保留和备份策略；网盘不是身份认证系统，也不能替代钉钉实名授权。

### 2. 管理员准备项目服务器

1. 安装 Python 3.11 或以上版本。
2. 将本项目完整放到项目私有根目录，不要只复制插件目录。
3. 复制 `config/dingtalk-qwen.env.example` 为部署环境的安全配置文件，并由启动脚本、服务管理器或容器注入进程；本项目不会自动读取 `.env` 文件。
4. 填写项目编号、造价系统编号、正式访问域名和钉钉配置；真实密钥只放在服务器安全配置中。
5. 确认 `data/` 目录权限只有项目管理员、应用服务账号和备份账号可读写。
6. 先用本地演示模式验证界面，再切换正式钉钉模式；正式模式不能用演示岗位下拉框代替登录。

本地验证命令：

```text
python -m unittest discover -s tests -v
python server.py
```

看到“运行中”后，管理员在电脑打开 `http://127.0.0.1:8765`。如果需要手机访问，在受控局域网中将环境变量设置为项目电脑的私有网卡地址。Windows PowerShell 示例：

```text
$env:MUNICIPAL_LOOP_HOST="192.168.1.20"
$env:MUNICIPAL_LOOP_PORT="8765"
python server.py
```

Linux/macOS 使用 `export MUNICIPAL_LOOP_HOST=192.168.1.20` 和 `export MUNICIPAL_LOOP_PORT=8765`。同时只在 Windows 防火墙中放行项目私网入站端口，禁止公网入站。演示模式只适合本机或测试网络；正式环境使用 `MUNICIPAL_LOOP_MODE=dingtalk`，并在 HTTPS 反向代理后运行。

### 3. 配置钉钉实名身份和人员归口

项目管理员在钉钉企业内部应用中配置 HTTPS 回调地址，然后在系统后台导入本项目成员。正式访问链路为：

```text
钉钉实名企业账号 → 企业成员匹配 → 项目成员名单 → 实名门禁 → 项目会话
```

岗位归口固定如下，不能由 AI 或普通用户临时改变：

| 归口 | 管理岗位 | 负责岗位 |
|---|---|---|
| 生产归口 | 生产经理 | 施工员/测量员、材料员、安全员 |
| 技术归口 | 技术负责人 | 质量员、实验员、资料员 |
| 造价归口 | 造价经理 | 造价验证及造价相关授权人员 |
| 综合归口 | 项目经理 | 生产经理、技术负责人、造价经理、行政/后勤 |
| 支持岗位 | 行政/后勤 | 行政、会议、车辆和后勤保障事项 |

操作要求：

1. 项目经理只使用已通过钉钉企业身份和实名认证核验的账号进入后台。
2. 新增成员先录入钉钉稳定用户 ID，再指定岗位和有效状态。
3. 成员必须完成受控实名复核后才能正式使用；不能让成员本人在浏览器勾选实名。
4. 离职、调岗或退出项目时，立即停用成员，旧会话失效后重新登录。
5. 正式模式不设置共享账号，不依赖“初始密码 123456”；初始密码仅可作为未接入身份系统的演示约定，不能用于正式项目。

### 4. 每个岗位怎样使用

所有岗位都从“我的任务”开始，只填自己的成果，不代替其他岗位填报：

1. 打开项目入口，确认系统显示的姓名、岗位和项目名称。
2. 选择本周或本月任务。
3. 填写工作日期、工程部位、实际数量、单位和成果说明。
4. 上传现场照片、测量记录、实验报告、材料合格证、会议记录或其他证据；手机端可直接拍照。
5. 提交后查看状态，不把“已提交”当成“造价合格”。
6. 下一周期填写本期成果、下期计划和未完成原因；月报在周报记录基础上汇总，不重复造一套数据。

岗位成果至少包括：

- 施工员/测量员：施工日志、测量记录、完成部位、现场照片；
- 材料员：进场、验收、领用、批次和合格证；
- 安全员：安全检查、隐患、整改和复查证据；
- 质量员：质量检查、不合格项、整改闭环；
- 实验员：取样、送检、报告编号和试验结果；
- 资料员：报验、签认、技术资料和文件状态；
- 行政/后勤：会议、通知、车辆、人员和后勤保障记录；
- 生产经理：生产计划、实际完成量、偏差和生产线审核；
- 技术负责人：技术措施、质量问题、技术线审核和复查结论；
- 造价经理：三证核对、计量依据、造价验证和进入造价系统的结果；
- 项目经理：项目总览、任务基线、人员归口和异常协调。

### 5. 三证互证和造价闭环

每一项需要进入造价系统的成果，按以下顺序流转：

```text
岗位原始成果/施工证
        ↓
生产归口审核 + 技术归口审核
        ↓
工程量、部位、规则和依据核对
        ↓
造价经理验证
        ↓
验证合格 → 造价系统导入/回执
```

三类证据不齐全时只能保持“待审核、待互证或退回补证”，不能由 AI 补猜。造价经理验证时至少核对：

- 生产证：施工日志、完成部位、实际数量、现场照片；
- 技术证：图纸、测量、质量、实验、技术措施或复查记录；
- 造价证：清单/定额口径、计量规则、合同依据和造价系统项目编号。

### 6. 图纸算量和 AI 插件使用

图纸算量插件只处理项目私有目录内的 ASCII DXF，固定顺序为：

```text
capabilities → inspect_dxf → 人工确认断面
→ calculate_retaining → get_job → 人工审核
```

AI 可以帮助解释、整理和生成草稿，但不能把图层识别直接当作设计事实，不能猜测断面、定额、单价或地质参数。计算结果属于 `Inference`，只有生产、技术和造价审核通过后才可能成为 `Fact`。

Codex 安装：

```text
codex plugin marketplace add .
codex plugin add municipal-cad-qto@municipal-project
```

Claude Code 和 WorkBuddy 使用 `plugins/municipal-cad-qto/adapters/` 中的对应配置；不要混用 `${PLUGIN_ROOT}` 与 `${CLAUDE_PLUGIN_ROOT}`。千问/百炼、豆包/扣子必须通过私有 HTTPS MCP 网关访问，不能让云端直接读取员工电脑上的本地文件。

### 7. 每日、每周和每月管理动作

每日由各岗位提交当日成果和证据，生产经理、技术负责人分别处理各自归口的待审记录。每周由项目经理查看未提交任务、退回补证、数据冲突和待造价验证；造价经理只处理已通过生产/技术互证的记录。每月生成月报，并将未完成事项转为下月任务，不删除原记录。

### 8. 备份、恢复和换电脑

1. 每日备份 `data/` 到项目私有备份位置，至少保留一个最近备份和一个周期备份。
2. 备份范围包含 `db.json`、`evidence/` 和 `cad_jobs/`，不包含密钥文件。
3. 恢复前停止服务，保留当前 `data/` 副本，再替换为已核验备份。
4. 换项目电脑时，只迁移经过核对的项目代码和私有数据；重新设置环境变量和钉钉回调，不复制浏览器会话。
5. 恢复后先检查项目编号、造价系统编号、成员名单、最近审核状态和文件哈希，再恢复使用。

### 9. 上线验收清单

- [ ] 所有人员进入的是同一个项目地址和同一个数据根目录。
- [ ] 项目编号与造价系统项目编号已核对。
- [ ] 钉钉登录、企业成员匹配和实名认证门禁全部通过。
- [ ] 生产经理、技术负责人、造价经理看到的管理范围不同。
- [ ] 施工员/测量员可以手机拍照提交施工日志和测量成果。
- [ ] 实验员、材料员、质量员、资料员、行政/后勤均能提交自己的岗位成果。
- [ ] 生产证、技术证、造价证未齐全时不能标记为验证合格。
- [ ] DXF 算量结果显示源图哈希、规则版本、公式和人工审核状态。
- [ ] HTTP 非本机绑定时已设置 Token，并置于企业私网或受控网关后。
- [ ] 已完成一次备份、恢复和成员停用测试。

### 10. 常见问题

**手机打不开地址：** 检查手机和项目电脑是否在同一受控网络、防火墙是否允许项目端口，以及 `MUNICIPAL_LOOP_HOST` 是否配置为项目电脑私有地址。正式环境优先使用 HTTPS 域名。

**登录后提示未加入项目：** 检查钉钉稳定用户 ID 是否在当前项目成员名单、成员是否有效，以及是否完成实名复核。

**AI 看不到图纸：** 这是数据边界设计。检查插件宿主是否指向同一项目私有根目录；云端千问/豆包必须访问私有 MCP 网关，不能依赖员工电脑本地路径。

**结果不能进入造价：** 检查是否完成生产和技术两条归口审核、证据是否完整、工程部位和清单编码是否一致。AI 不能跳过造价经理验证。

**需要停用或回退：** 停止服务、撤销远程 MCP 路由或禁用宿主插件即可；不要删除原始图纸、证据和历史作业。

### 11. 当前版本边界

这是单项目轻量 MVP，适合一个项目部的小规模试运行。当前结构化数据使用本地 `data/db.json`，尚未引入高并发数据库、自动造价系统正式接口、DWG/PDF/IFC/LandXML 转换器或跨项目租户管理。正式扩大并发人数、启用多项目或接入正式造价系统前，应先完成容量、并发写入、接口回执和权限复测，不要直接把当前演示服务当作公网 SaaS 使用。
