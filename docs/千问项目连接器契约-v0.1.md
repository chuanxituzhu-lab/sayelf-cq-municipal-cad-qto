# 千问项目连接器契约 v0.1

## 1. 目标

让项目人员只通过千问进入系统，后台预先接入项目数据、文件存储、工作流和造价验证功能。

```text
钉钉工作台 → 千问项目入口 → 项目连接器 → 私有项目后台
```

普通人员不配置接口，不选择数据库，不输入项目编号，不手工切换岗位。

## 2. 入口和身份

1. 钉钉作为企业身份提供方。
2. 千问组织绑定钉钉 SSO。
3. 项目后台根据钉钉稳定用户 ID 查询项目成员表。
4. 后台返回当前项目、岗位、归口和数据范围。
5. 千问只展示后台返回的可用功能。

后台必须自行校验：

```text
user_id
project_id
role_code
management_line
action
```

不允许仅凭千问会话内容判定权限。

## 5. 最小工具接口

| 接口 | 用途 | 是否改变关键数据 |
|---|---|---:|
| get_user_context | 获取当前岗位和项目范围 | 否 |
| list_my_tasks | 获取本人任务 | 否 |
| submit_work_record | 提交岗位成果 | 是 |
| upload_evidence | 上传照片或附件 | 是 |
| compare_periods | 对比本期与上期任务成果 | 否 |
| list_missing_evidence | 获取证据缺口 | 否 |
| submit_line_review | 提交生产/技术审核 | 是 |
| get_cost_validation_queue | 获取待造价验证数据 | 否 |
| submit_cost_validation | 提交造价验证结论 | 是 |
| generate_period_report | 生成周报/月报草稿 | 否 |
| export_verified_cost_facts | 导出合格造价事实 | 是 |

所有接口统一返回：

```text
request_id
project_id
record_id（如有）
status
message
next_action
```

## 6. AI 行为限制

千问可以：

- 解释业务数据；
- 生成报告草稿；
- 提醒逾期和缺证；
- 提示数量、日期和部位冲突；
- 推荐下一步动作。

千问不能：

- 自行修改原始工程量；
- 自行改变项目或岗位权限；
- 自行通过生产、技术审核；
- 自行通过造价验证；
- 自行删除证据；
- 自行跨项目查询。

## 7. 预接入功能

由管理员或部署程序提前配置：

```text
钉钉身份
项目数据库
私有文件存储
岗位权限
周/月任务流程
三证互证规则
造价系统接口
消息提醒
报表模板
```

用户端只保留一个项目入口。

## 8. 验收条件

- 普通用户从钉钉进入后无需再次输入项目编号。
- 首次授权后可以直接看到自己的岗位工作台。
- 用户无法读取不属于自己的项目数据。
- 手机可以直接拍照提交工程证据。
- 造价验证队列中的每条记录都能回溯生产证和技术证。
- AI 的异常提示不会自动改变数据状态。
- 造价系统只接收验证合格的数据。
