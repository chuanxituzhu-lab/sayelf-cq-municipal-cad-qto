# 八项底座构建原则：项目执行清单

版本：v0.1
适用范围：本项目所有后续设计、编码、接入、自动化和 WebUI 变更

本清单采用 `sayelf-build-principles` 作为规范来源，不复制规范正文；这里记录本项目的落地映射、检查证据和未完成项。

## 执行门禁

每项新能力进入实现前必须完成：

```text
搜索现有能力 → 比较与缺口分析 → 分类决策
→ 构建决策记录 → 最小实现 → 聚焦验证
→ 数据泄露检查 → 版本化/灰度/回滚准备
```

缺少可量化差异、验证证据或数据边界时，不进入正式实现和外部发布。

## 八项原则映射

| 编号 | 原则 | 当前项目落地 | 检查证据 |
|---|---|---|---|
| 01 | Negative Entropy | 只保留 DXF 标准化、候选识别、挡护结构规则、证据输出和审核状态；不把 BIM、ERP、全自动造价等放进当前核心 | [图纸算量 BDR](./重庆市政图纸算量-BDR-v0.1.md) 的“最小 Core/明确不建设” |
| 02 | Modular / Pluggable | `cad_qto.dxf`、`canonical`、`recognition`、`retaining`、`job` 分层；DWG/PDF/IFC/LandXML 作为后续可替换适配器 | [模块代码](../cad_qto/) 与 BDR 的“插件边界” |
| 03 | Local-first | DXF 解析、几何统计、规则计算、哈希、结果保存均在本地执行；不依赖云端模型才能完成确定性核心 | [README](../README.md) 与本地回归测试 |
| 04 | Dynamic by State | 作业按 `DRAFT → PARSED → NORMALIZED → CALCULATED → REVIEW_REQUIRED → APPROVED` 推进；文件哈希、规则版本变化、告警和单位异常触发下一次检查 | BDR 的“状态、变更信号与下一次检查” |
| 05 | Intelligent Automation | `Observation/Inference/Hypothesis/Fact` 分层；图层语义只产生候选假设，公式结果是待审核推断，只有三方审核后才可成为事实 | 算量输出的 `status`、`review_status`、`evidence_refs` |
| 06 | Evidence-driven Evolution | 规则包显式版本化；合成样例和回归测试先行；真实脱敏图纸双算后再灰度；保留输入/输出快照以支持回滚 | [字段与测试基线](./重庆市政图纸算量-字段与测试基线-v0.1.md) |
| 07 | WebUI as Human Interface | 现有 WebUI 提供 `打开项目 → 输入图纸/断面 → 执行 → 查看结果`；关键规则、告警、哈希和审核状态对审核人员可见 | [主页面](../web/index.html) 的“图纸算量”入口 |
| 08 | Local Data & Sensitive Data Sovereignty | 原图、标准化图、结果、项目账本留在项目私有目录；接口拒绝项目目录外路径和公开 URL；密钥只从安全环境读取；公开发布默认阻断 | `server.py` 的项目路径校验、数据目录检查、环境变量模板 |

## 数据与发布结论

- 真实施工图、合同、照片、项目账本、造价文件、人员信息和认证凭据：`Sensitive/Restricted`，只留在项目私有信任边界。
- 合成样例、脱敏代码、公开标准链接和本执行清单：只有在逐项检查后才可标记为 `Public`。
- GitHub、公共网站、外部模型、第三方 API 和遥测：默认 `Blocked`；除非明确授权、最小化脱敏、确认目的地/保留周期并完成泄露检查。

## 当前证据与缺口

已完成：

- Step 0 开源与现有能力调研，并判定本增量为 `Improve`；
- 本地 DXF/挡护结构最小闭环；
- 5 项回归测试、隔离接口 POST/保存/查询测试；
- 语法检查、服务状态接口检查、项目数据目录无合成残留检查。

仍未完成：

- 真实重庆项目脱敏 DXF 与人工底稿双算；
- DWG 本地转换器的许可证、版本和失败样本验证；
- 重庆正式清单/定额映射和计价口径的证据绑定；
- 审核通过后进入现有造价系统的人工导出/接口验收。

以上缺口未关闭前，系统不得宣称生产级全自动算量，也不得自动入账。
