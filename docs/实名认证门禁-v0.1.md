# 钉钉实名认证门禁 v0.1

## 1. 三道门槛

正式模式只有同时满足以下条件，才允许进入项目：

```text
钉钉认证身份
    ∩ 企业成员身份
    ∩ 项目成员名单
    ∩ 实名核验通过
```

任何一项不满足，都拒绝进入项目数据。

## 2. 身份来源

- 用户身份必须来自钉钉企业应用授权或企业单点登录。
- 后台使用钉钉稳定用户 ID 绑定项目成员，不使用姓名作为唯一身份。
- 项目成员姓名、岗位和归口由项目管理员维护。
- 用户不能在浏览器、千问对话或表单中自行填写“已实名”。
- 账号、姓名或组织关系发生变化时，需要重新同步或由管理员复核。

## 3. 实名状态

成员记录包含：

```text
identity_source
real_name_verified
verified_at
verified_by
```

正式模式只有以下条件同时成立时才通过：

```text
identity_source = dingtalk_enterprise
real_name_verified = true
active = true
```

本地演示模式不代表真实实名认证，只用于测试页面和工作流。

## 4. 拒绝状态

| 状态 | 返回结果 |
|---|---|
| 没有钉钉认证身份 | 未认证，拒绝进入 |
| 不是企业成员 | 无企业成员身份，拒绝进入 |
| 未加入当前项目 | 不属于项目成员，拒绝进入 |
| 实名未核验 | 实名核验未通过，拒绝进入 |
| 账号已停用 | 项目访问已撤销 |

## 5. 不采用的方式

- 不使用共享账号。
- 不使用初始密码作为正式登录方式。
- 不使用手机号或姓名单独认定实名。
- 不允许前端传入岗位后直接获得权限。
- 不允许通过修改 URL 参数切换人员或项目。
- 不把千问会话身份当作项目最终权限依据。
