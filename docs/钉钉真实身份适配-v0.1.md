# 钉钉真实身份适配 v0.1

## 目标

正式模式采用钉钉企业应用授权，不使用共享账号、初始密码或浏览器传入岗位作为登录依据：

```text
钉钉授权码 → 用户访问令牌 → 稳定用户 ID → 企业/项目成员名单 → 实名门禁 → 项目会话
```

## 已实现的服务端行为

- `/auth/dingtalk/start` 生成一次性 `state`，有效期 5 分钟，并跳转钉钉授权页。
- `/auth/dingtalk/callback` 校验 `state`，交换用户访问令牌并取得用户信息。
- 仅允许配置的企业 ID、当前项目成员名单中的有效成员进入。
- 成员必须满足 `identity_source=dingtalk_enterprise` 与 `real_name_verified=true`。
- 登录成功后只下发 HttpOnly、SameSite 会话 Cookie；会话保存在服务内存，服务重启后自动失效。
- 退出登录会删除服务端会话并清除 Cookie。
- 不保存访问令牌、不保存完整钉钉用户信息、不把用户信息写入 GitHub 或公共网络。

## 部署前配置

复制 `config/dingtalk-qwen.env.example` 到部署环境的安全配置，填写：

- 钉钉企业 ID、客户端 ID、客户端密钥；
- HTTPS 回调地址：`https://项目私有域名/auth/dingtalk/callback`；
- 千问企业组织/连接器编号；
- 单项目固定编号。

默认 OAuth 地址按标准配置提供，也支持通过 `DINGTALK_AUTH_URL`、`DINGTALK_TOKEN_URL`、`DINGTALK_USERINFO_URL` 覆盖。不同钉钉应用类型和版本的接口字段可能不同，上线前必须用本项目租户做一次授权码、企业归属、稳定用户 ID 和实名字段联调。

## 实名核验边界

钉钉授权本身证明“这个请求来自某个钉钉企业身份”，不应在没有租户联调证据时臆定某个用户信息字段一定代表实名。当前适配器允许配置实名断言字段；如果钉钉用户信息接口不提供该字段，则必须由受控的项目成员导入/复核流程将 `real_name_verified` 置为 true，用户本人和前端均不能修改。

## 可信代理选项

默认 `MUNICIPAL_LOOP_TRUSTED_PROXY=false`。只有前置网关已经完成钉钉验签、并且服务器与网关之间是受控链路时，才可以开启并使用 `X-DingTalk-User-Id`。普通浏览器直接发送该请求头不能作为身份凭据。

## 项目后台

正式模式的 `/admin.html` 只允许已通过实名认证门禁、且岗位为“项目经理”的成员访问。项目经理可以维护项目基础信息、人员名单、岗位和有效状态；生产经理、技术负责人、造价经理的审核权限仍按各自归口执行，不能借后台设置互相越权。

新增成员先处于 `pending_roster`，必须完成受控实名复核后才能进入正式项目。后台勾选实名复核时会记录 `verified_by` 和 `verified_at`；如果租户能提供钉钉实名断言，则以断言为优先。

## 验收清单

1. 未登录访问 `/api/bootstrap`：返回 401。
2. 非项目成员登录：返回 403。
3. 实名门禁未通过：返回 403。
4. 已通过成员进入：角色由服务器名单确定，前端不能切换岗位。
5. 退出登录或服务重启：旧会话不能继续访问。
6. 日志、`data/db.json` 和项目目录中均不得出现客户端密钥、用户访问令牌或完整用户信息。
