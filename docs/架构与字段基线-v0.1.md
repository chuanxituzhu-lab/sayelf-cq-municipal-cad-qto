# 单项目闭环系统架构与字段基线

## 1. 总体架构

```text
千问项目入口
    ↓
项目连接器
    ↓
私有项目闭环系统
    ├── 身份与权限
    ├── 项目底座
    ├── 岗位工作台
    ├── 工程证据中心
    ├── 三证互证中心
    ├── 造价事实中心
    ├── 周月报中心
    └── 审计与备份
    ↓
现有造价系统
```

钉钉是统一身份和启动入口，千问是统一智能入口。所有业务动作必须通过项目连接器调用后台接口，后台再次校验人员身份、岗位、项目编号和操作权限。

## 1.1 用户接入方式

### 管理员一次性配置

```text
钉钉创建企业内部应用
→ 千问组织绑定钉钉 SSO
→ 项目后台配置项目连接器
→ 配置人员、岗位和管理归口
→ 在钉钉工作台发布“市政项目管理”入口
```

### 普通人员使用

```text
钉钉工作台
→ 打开“市政项目管理”
→ 首次授权一次
→ 自动进入千问项目入口
→ 自动显示本人岗位工作台
```

普通人员不需要单独配置数据库、文件存储、造价接口或 AI 连接器。钉钉账号是身份来源，千问账号不单独维护一套项目成员名单。

### 两种接入方式取舍

| 方式 | 适用场景 | 决策 |
|---|---|---|
| 每个用户分别授权钉钉应用 | 临时试用、人数少、没有企业统一管理 | 备用 |
| 千问组织绑定钉钉 SSO，再从钉钉工作台进入 | 正式项目、岗位归口、人员离岗和权限撤销 | 采用 |

钉钉只提供身份和启动入口，项目业务数据仍存放在私有项目系统中。

## 2. 统一岗位归口

| 管理归口 | 管理岗位 | 归口人员 |
|---|---|---|
| 生产归口 | 生产经理 | 施工员/测量员、材料员、安全员 |
| 技术归口 | 技术负责人 | 质量员、实验员、资料员 |
| 造价归口 | 造价经理 | 造价、合同、计量、签证人员 |
| 项目综合归口 | 项目经理 | 生产经理、技术负责人、造价经理、行政/后勤 |
| 支持岗位 | 行政/后勤 | 行政和后勤事项 |

施工员/测量员是一个岗位，工作类别可以是施工或测量。行政/后勤是一个岗位，工作类别可以是行政或后勤。

## 4. 状态机

```text
待填报
  ↓
已填报
  ↓
待本线审核
  ↓
待交叉验证
  ↓
待造价验证
  ↓
验证合格
  ↓
已进入造价系统
```

异常状态：

```text
证据不足 / 数据冲突 / 责任人不明 / 退回补证 / 拒绝入账
```

## 5. 千问项目连接器的最小接口

```text
get_current_user_context
list_my_tasks
submit_work_record
upload_evidence
get_my_pending_items
compare_period_results
get_validation_status
generate_weekly_report
generate_monthly_report
submit_line_review
submit_cost_validation
export_verified_cost_facts
```

接口必须统一接收：

```text
user_id
project_id
role_code
request_id
```

后台不得信任千问传入的岗位和项目权限，必须根据 `user_id` 重新查询项目成员表。

## 6. 权限原则

| 岗位 | 主要操作 | 数据范围 |
|---|---|---|
| 施工员/测量员 | 填报施工、测量、照片 | 自己负责的任务和部位 |
| 生产经理 | 生产线审核、进度督办 | 生产归口 |
| 技术负责人 | 技术线审核、质量技术判断 | 技术归口 |
| 造价经理 | 造价验证、合格入账 | 通过授权的全项目证据 |
| 项目经理 | 看板、异常、综合协调 | 项目汇总数据 |
| 行政/后勤 | 行政和后勤填报 | 本岗位数据 |
| 系统管理员 | 成员、岗位、项目设置 | 仅限系统管理，不替代业务审核 |

## 7. 事实分层

```text
Observation  原始观察：照片、日志、测量、实验结果
Inference    系统推断：统计数量、周期汇总、偏差计算
Hypothesis   AI假设：可能缺证、可能冲突、可能逾期
Fact         合格事实：经审核并可进入造价系统的数据
```

只有 `Fact` 才能进入造价系统。AI 生成的内容默认属于 `Hypothesis`，必须经过人员确认。
