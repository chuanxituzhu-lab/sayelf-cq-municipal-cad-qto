# 权限矩阵与数据字典 v0.1

## 1. 权限范围

权限由四个维度组成：

```text
项目范围 + 管理归口 + 数据对象 + 操作动作
```

### 数据范围

| 范围 | 含义 |
|---|---|
| SELF | 本人提交或被分配的记录 |
| LINE | 本管理归口下的记录 |
| PROJECT | 当前项目内的授权记录 |
| SYSTEM | 系统配置和权限管理 |

普通用户默认只能访问当前项目，不能通过修改请求参数读取其他项目。

## 2. 角色权限矩阵

符号说明：`C` 创建，`R` 查看，`U` 修改，`A` 审核，`V` 造价验证，`X` 导出，`-` 无权限。

| 角色 | 任务 | 岗位成果 | 现场证据 | 本线审核 | 交叉验证 | 造价验证 | 报表 | 项目配置 |
|---|---|---|---|---|---|---|---|---|
| 项目经理 | R/U | R/C | R | A | A | R | R/X | - |
| 生产经理 | R/U | R/C | R/C | A | A | R | R/X | - |
| 技术负责人 | R/U | R/C | R/C | A | A | R | R/X | - |
| 造价经理 | R/U | R/C | R | - | A | V/X | R/X | - |
| 施工员/测量员 | R | C/U | C/U | - | - | - | R | - |
| 材料员 | R | C/U | C/U | - | - | - | R | - |
| 安全员 | R | C/U | C/U | - | - | - | R | - |
| 质量员 | R | C/U | C/U | - | - | - | R | - |
| 实验员 | R | C/U | C/U | - | - | - | R | - |
| 资料员 | R | C/U | C/U | - | - | - | R | - |
| 行政/后勤 | R | C/U | C/U | - | - | - | R | - |
| 系统管理员 | - | - | - | - | - | - | - | C/R/U |

说明：

- `R` 不代表可以查看项目全部敏感内容，仍需经过字段级和数据范围过滤。
- 系统管理员可以维护人员和配置，但不替代生产、技术、造价业务审核。
- 造价经理只能验证已经形成证据链的记录，不能凭空创建合格造价事实。

## 3. 管理归口规则

```text
生产归口：生产经理 → 施工员/测量员、材料员、安全员
技术归口：技术负责人 → 质量员、实验员、资料员
造价归口：造价经理 → 造价、合同、计量、签证人员
综合归口：项目经理 → 生产经理、技术负责人、造价经理、行政/后勤
```

岗位归口是确定的，AI 不得动态改变归口。人员岗位变更必须由管理员修改项目成员表后生效。

## 4. 业务对象与必填关联

| 对象 | 必填关联 | 用途 |
|---|---|---|
| 任务基线 | project_id、period_id、role_code、responsible_user_id | 规定本期任务和要求成果 |
| 岗位成果 | task_id、responsible_user_id、work_date、status | 记录岗位实际完成情况 |
| 工程证据 | record_id、evidence_type、captured_by、captured_at | 支撑成果和工程事实 |
| 审核记录 | record_id、review_line、reviewer_user_id、review_result | 记录生产/技术/造价审核 |
| 三证互证 | record_id、production_evidence、technical_evidence、cost_evidence | 判断证据是否完整一致 |
| 造价事实 | boq_code、verified_quantity、evidence_ids、validation_result | 作为造价系统输入 |

## 5. 事实分层

| 层级 | 允许来源 | 是否可进入造价系统 |
|---|---|---:|
| Observation 原始观察 | 人员填报、照片、测量、实验报告 | 否 |
| Inference 系统推断 | 统计、换算、周期汇总 | 否 |
| Hypothesis AI 假设 | 缺项提示、冲突提示、风险判断 | 否 |
| Fact 合格事实 | 生产、技术、造价审核通过 | 是 |

## 6. 状态迁移权限

| 当前状态 | 下一状态 | 允许动作人 | 必要条件 |
|---|---|---|---|
| 待填报 | 已填报 | 责任人 | 必填字段完成 |
| 已填报 | 待本线审核 | 系统 | 记录提交成功 |
| 待本线审核 | 待交叉验证 | 归口负责人 | 本线审核通过 |
| 待本线审核 | 退回补证 | 归口负责人 | 证据不足或内容不清 |
| 待交叉验证 | 待造价验证 | 生产/技术审核人 | 两线证据能够关联 |
| 待交叉验证 | 数据冲突 | 系统/审核人 | 数量、日期或部位冲突 |
| 待造价验证 | 验证合格 | 造价经理 | 三证完整且数量可追溯 |
| 待造价验证 | 退回补证 | 造价经理 | 计价依据或证据不足 |
| 验证合格 | 已进入造价系统 | 造价接口/造价经理 | 入账回执成功 |

## 7. 安全约束

- `project_id` 不信任客户端传入值，以登录用户的项目成员关系为准。
- `role_code` 不信任千问传入值，以项目成员表为准。
- 所有修改写入内部审计事件，原始观察记录不直接覆盖。
- 删除采用业务作废，不物理删除已参与审核或造价验证的记录。
- 文件下载必须经过权限校验和临时授权，不暴露永久公开链接。
- 造价系统接口只接收 `Fact` 层数据。
