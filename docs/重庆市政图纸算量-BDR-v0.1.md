# 重庆市政施工图识别与工程量计算构建决策记录

版本：v0.1
日期：2026-08-28
适用范围：重庆市政施工项目的本地试运行原型

## 1. 真实任务与 Step 0 结论

真实任务不是“让 AI 看懂图纸并直接出造价”，而是把施工图中的可重复几何信息转成可追溯的工程量草稿，减少重复量取工作；最终工程事实仍由生产、技术、造价人员审核确认。

已检索当前工作区、GitHub 和开源生态。成熟能力主要分散在 DXF 读写、CAD 预览、PDF 本地量取、IFC 解析、土方体积计算和通用工程平台中，没有找到同时覆盖“中文市政语义 + 重庆计价口径 + 挡护结构 + 证据审核 + 本地数据边界”的成熟开源成品。

本次分类：**Improve**。

采用的参考能力：

- [ezdxf](https://github.com/mozman/ezdxf)：DXF 读写基础，MIT；
- [Aspicio](https://github.com/frontsail-ai/aspicio)：本地 CAD/PDF 几何预览与实体展开思路，MIT；
- [OpenTakeoff](https://github.com/Kentucky-ai/opentakeoff)：量取证据、比例和审计轨迹思路，Apache-2.0；
- [IFCOpenShell](https://docs.ifcopenshell.org/introduction.html)：存在 BIM/IFC 时的模型侧数量来源；
- [AEC QTO](https://github.com/aec-platform/qto)：版本化规则映射思路，MIT；
- [Volume-Solver](https://github.com/howtocivilengineer/Volume-Solver)：土方断面复核思路。

以下项目只作架构或能力参考，不作为本项目直接依赖：存在低成熟度、非商业许可、云端上传或开源许可证不适配风险的项目，必须单独审查。

## 2. 可量化差异与成功证据

本次增量必须同时满足：

1. 一份 ASCII DXF 可以被解析、标准化并生成哈希和转换日志；不支持的实体不得静默丢失。
2. 一组明确输入的挡护结构断面，可以生成可复核的工程量、公式、输入值、单位、来源和审核状态。
3. 计算结果默认是 `Inference`，不能直接成为 `Fact` 或自动进入造价系统。
4. 任何缺少关键尺寸、图层语义不明确或实体类型不支持的情况，都产生 `Hypothesis/ReviewRequired` 标记。
5. 通过本地合成 DXF 和回归测试验证：挡墙、基础、土方、回填、泄水孔、反滤层、锚杆、抗滑桩、喷射混凝土/钢筋网等规则的数值稳定可复算。

试运行门槛：连续两个周周期和一个月周期；每一条进入造价验证的数据都有原图哈希、标准化图哈希、规则包版本、公式、输入、人工审核记录。未达到门槛前不自动写入现有造价系统。

## 3. 最小 Core

```text
ASCII DXF
  → 解析支持实体
  → 标准化 DXF + SHA-256 + 转换日志
  → 图层/实体清单与候选语义（Hypothesis）
  → 人工确认的挡护结构断面参数
  → 确定性规则计算
  → 工程量明细 + 公式 + EvidenceRef
  → 待人工审核
```

第一片只做：

- LINE、LWPOLYLINE、TEXT、MTEXT 的保守解析；
- 图层长度、闭合状态、文本清单和不支持实体告警；
- 重力式/悬臂式等挡墙的墙身、基础、开挖、回填、泄水孔、反滤层；
- 锚杆、抗滑桩、喷射混凝土、钢筋网的显式参数计算；
- 本地 CLI/API 可调用的 JSON 输入输出；
- 与现有项目审计账本的最小接入。

## 4. 插件边界

- `cad_qto.dxf`：DXF 解析和标准化，不负责市政判断。
- `cad_qto.recognition`：图层/实体候选识别，只产生假设，不产生合格事实。
- `cad_qto.retaining`：挡护结构确定性规则，规则版本化。
- `cad_qto.job`：输入、输出、哈希、告警和证据组装。
- 未来 DWG 转换器、PDF/OCR、IFC、LandXML、重庆定额/清单映射均为可替换边界，不在本片硬编码。

## 5. 本地优先与数据分类

- 原始 DWG/DXF/PDF/IFC/LandXML、标准化 DXF、识别结果和审核记录均属于项目私有数据，只留在本机或项目私有存储。
- GitHub/公开网络只允许公开的代码、脱敏合成样例、公开标准链接和文档，不允许真实图纸、合同、照片、造价文件、密钥、日志和元数据外传。
- DXF 是 2D CAD 的统一交换层，不强迫 PDF、IFC、LandXML 失去原生语义；DWG 仅通过本地、可审查的转换器接入。

## 6. 状态、变更信号与下一次检查

任务状态：`DRAFT → PARSED → NORMALIZED → CALCULATED → REVIEW_REQUIRED → APPROVED`。

出现以下信号必须停在人工复核：输入哈希变化、规则包变化、实体不支持、图层匹配不唯一、关键尺寸缺失、图形与手工断面不一致、数量越界或单位不一致。

下一次检查点：用至少一份真实项目脱敏 DXF 与人工底稿进行双算，比较分项数量、漏项、误识别和人工修订原因；未经此检查，不宣称达到生产级自动算量。

## 7. 事实分层

- `Observation`：原始实体、图层、文字、文件哈希、人工录入尺寸。
- `Inference`：由明确公式推导的数量和图层统计。
- `Hypothesis`：根据图层名/文字猜测的构件类别或缺失信息提示。
- `Fact`：通过生产、技术、造价审核后的可入账数据。

## 8. 演进、版本、灰度与回滚

- 规则包使用显式版本号；同一输入必须可重算并得到同一结果。
- 新规则先在合成数据和测试项目运行，再灰度到真实项目；差异超阈值时保留旧规则结果。
- 每个算量作业保留源文件哈希、标准化文件哈希、规则版本、输入快照和输出快照。
- 回滚只切换规则版本或删除未审核的草稿作业，不删除原始图纸、原始观察和已审核事实。

## 9. WebUI 决策

需要 WebUI，因为实际工作流必须是 `打开项目 → 选择图纸/输入断面 → 执行 → 查看结果与证据 → 人工审核`。本次先实现可调用的本地核心与 API；现有项目 WebUI 仅增加“图纸算量”入口，显示规则版本、告警和审核状态，不隐藏关键假设。

## 10. 明确不建设

- 不在本片实现通用 DWG 解析器；
- 不把 OCR/视觉模型的猜测直接作为工程量；
- 不自动判断施工图设计意图、地质参数或重庆定额子目；
- 不自动审批、不自动签证、不自动写入造价系统；
- 不建设多项目平台、BIM 全专业自动算量或复杂 ERP。
