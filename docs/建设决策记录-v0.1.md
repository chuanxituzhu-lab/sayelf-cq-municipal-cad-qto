# 市政工程岗位成果闭环系统

## 1. 建设决策

- 建设范围：单个市政工程项目。
- 建设方式：清洁室式全新开发，只参考公开项目的业务方法，不复制外部代码、资源和项目数据。
- Step 0 分类：Differentiate。
- 产品定位：以造价为核心，生产与技术为两翼，以三证互证形成工程数据闭环。
- 使用入口：钉钉工作台启动，千问作为智能入口；电脑端和手机端均可使用。
- 身份策略：钉钉企业身份一次绑定千问组织，项目后台按企业用户 ID 自动匹配岗位。
- 数据主库：私有项目闭环系统。
- 文件主库：项目专用私有文件存储。
- 造价主库：现有造价系统中的合格造价事实。

## 2. 必须解决的问题

1. 岗位人员能够提交本周/本月成果和下周/下月计划。
2. 系统能够自动比较本期成果与上期任务要求。
3. 施工员/测量员、实验员、材料员、安全员、质量员、资料员、行政/后勤等岗位的工作成果均可结构化保存。
4. 生产经理、技术负责人、造价经理分别管理自己的人员和数据范围。
5. 生产证、技术证、造价证能够相互关联、相互验证。
6. 只有验证合格的数据才能进入造价系统。
7. 普通人员只需登录千问并进入项目，不需分别配置其他工具。
8. 项目原始资料、照片、合同和造价数据不进入 GitHub 或公开网络。

## 3. 可量化的试运行目标

以下是试运行目标，不是未经验证的事实：

- 普通岗位首次进入项目不超过 3 步。
- 一条现场成果从手机录入到提交不超过 2 分钟。
- 100% 的业务记录带有唯一项目编号。
- 100% 进入造价验证的数据都能追溯到生产证和技术证。
- 0 条跨项目越权读取记录。
- 项目周报生成后，人工整理时间控制在 5 分钟以内。
- 现场试运行两个周周期、一个月周期后，再决定是否自动推送造价系统。

## 4. 安全和数据边界

- 千问是统一入口和智能助手，不是工程数据主库。
- 原始照片、实验报告、合同和造价文件留在私有存储。
- AI 只能读取当前人员有权访问的数据。
- AI 不得修改工程量、批准签证或绕过造价验证。
- 普通用户不显示系统内部审计细节；管理员和授权审核人可以查看。
- 普通用户不配置数据库、文件库、造价接口或连接器；全部由项目管理员预先完成。
- 本系统保留自身的操作审计和数据修订记录，用于防止工程数据被无痕修改。
- 不使用公共分享链接作为正式权限，不使用个人网盘作为项目主存储。

## 5. 接入决策

采用“钉钉入口 + 千问绑定 + 私有项目后台”的组合方式：

```text
钉钉工作台
    ↓ 一次登录/授权
千问办公
    ↓ 项目连接器
私有项目闭环系统
```

- 钉钉负责企业身份、成员状态和项目启动入口。
- 千问负责对话、岗位专家能力和报告生成。
- 项目后台负责岗位权限、项目隔离、证据保存、审核状态和造价验证。
- 项目人员不需要分别登录或配置宜搭、网盘、数据库和造价接口。
- 单个用户首次进入时如需授权，只完成一次；之后由企业身份自动登录。
- 后台不信任千问传入的岗位和权限，每次接口请求都用钉钉用户 ID 重新校验。

“钉钉每人单独授权”只作为试运行备用方案；正式项目采用企业级绑定和单点登录，便于人员离岗、岗位调整和权限撤销。

## 5. 最小核心

第一版只实现：

```text
人员与岗位
→ 周/月任务基线
→ 岗位成果
→ 手机照片和文件证据
→ 生产/技术归口审核
→ 三证互证
→ 造价经理验证
→ 周报/月报
```

暂不建设 BIM、CAD 自动算量、招投标、供应商门户、多项目组合管理和复杂 ERP 功能。

## 6. 演进和回滚

- 表单、岗位规则、互证规则和接口均采用内部版本号。
- 规则修改先在测试项目或测试周期运行，再进入正式项目。
- 造价接口先采用人工导出校验，确认数据稳定后再开启自动同步。
- 任一接口失败时，原始记录仍保留，允许人工导出至造价系统。
- 不删除原始观察记录；更正通过“补充/修订记录”完成。
